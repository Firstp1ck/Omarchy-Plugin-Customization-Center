What changed

Core

Crash recovery now uses durable evidence

The journal records the operation in flight, inverse progress, and inverse ordering. Recovery reconciles local filesystem effects only when exact evidence proves the result. Commands, IPC, reloads, and handoffs remain ambiguous after a crash and are never rerun by guesswork.

Rollback

Directory undo is conflict-safe

Directory replacement rollback binds the staged pre-image, observed installed image, raw forward result, original target image, and generated previous-directory identity. Missing, changed, malformed, or contradictory evidence preserves every candidate and records rollback_conflict.

Plans

Review and apply use the same draft

Monitor activation, mode export, and theme save generate volatile timestamps during validation and keep them in the normalized draft. ApplyBar.qml applies that exact draft. A failed re-review clears the old plan instead of leaving a stale Apply target enabled.

Integration

Module-specific edge cases are bounded

Monitor caches remain display-only. Plugin handoffs keep fallback polling. Mode import rewrites renamed monitor profile references. Generic pytest collection includes root tests and every registered module suite without failing on missing optional directories.

Important regression cases
  • Recovery never repeats ambiguous commands, shell IPC, reloads, or handoffs.
  • Completed inverses are not rerun after another crash.
  • Managed blocks require the exact expected post-image, including legacy fail-closed behavior.
  • Directory undo rejects a changed current target, changed previous directory, alternate clone sibling, contradictory install state, malformed raw result, and incomplete legacy evidence.
  • Monitor plans reject stale plan contexts and reuse the reviewed context without digest drift.
  • A failed second review clears the old Apply target.

Accepted residuals

  • A cross-filesystem rename-gap crash may leave one exact incoming sibling directory. Cleanup remains manual rather than broadening automatic deletion.
  • Legacy directory replacement records without complete post-image evidence stop in rollback_failed and require manual recovery.
  • Journal evidence is not cryptographically authenticated. Coordinated journal tampering is outside the local trusted-user threat model.
  • Serialized command output is capped. Truncated directory evidence fails closed and may require manual recovery.
